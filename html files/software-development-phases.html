Introduction

This project is based on the Software Development Life Cycle. In this assignment I have selected an AI Interview Platform as the real world system. The platform helps interviewers create interview sessions, generate questions from a job description, collect candidate responses through video and speech, and analyze those responses using AI-based scoring. It is useful for companies, HR teams, technical interviewers, and candidates who need a structured remote interview process.

In many organizations, first-round interviews consume a lot of time and are difficult to scale. Manual interviews also suffer from inconsistency because different interviewers may ask different questions or use different evaluation standards. This project solves that problem by providing one centralized platform where the interviewer can prepare the interview once and evaluate many candidates asynchronously.

Objectives of the Project

  • To solve a practical hiring problem: The project addresses the difficulty of managing first-round interviews manually for many candidates.
  • To study the existing process: The project examines how interview scheduling, questioning, and evaluation are usually handled manually.
  • To build a guided interview system: The system uses interviewer avatar media, browser speech, subtitles, timers, and video recording.
  • To generate smart questions: Questions are created from the job description and can be personalized further using candidate resume details.
  • To automate assessment: The platform scores candidate responses using structured AI analysis and local fallback heuristics.
  • To support integrity review: The system records phone detection and related signals during the interview for later human review.
  • To maintain useful records: The system stores sessions, candidates, transcripts, scores, and summaries in a structured manner.
  • To understand SDLC phases: The assignment shows planning, requirement analysis, design, implementation, and testing in sequence.

Project Scope

  • The system allows interviewers to create interview sessions with title, description, questions, time limits, weights, and evaluation criteria.
  • The system allows AI-based generation of interview questions from a job description.
  • The system allows candidates to register through a shared link and optionally upload resume information for personalization.
  • The system conducts an interview through avatar playback, speech synthesis, speech recognition, and video or audio recording.
  • The system analyzes candidate answers using AI or local fallback logic and generates summaries and rankings.
  • The system supports integrity event tracking such as phone-detection review signals.
  • The first version does not include enterprise authentication, online payments, or live multi-interviewer video conferencing.

Phase 1: Problem Definition and Planning

Problem Statement

In traditional recruitment, interviewers spend significant time repeating the same introductory questions for many candidates. Shortlisting becomes slow, candidate evaluation may differ from one interviewer to another, and remote interviews are difficult to monitor consistently. A browser-based AI Interview Platform can reduce repeated manual effort by providing a reusable interview workflow, structured evaluation criteria, and digital records of every candidate response.

System Objectives

  • To reduce manual first-round interview effort.
  • To maintain consistent interview questions and scoring logic.
  • To support candidate-specific question personalization from resumes.
  • To capture transcripts, recordings, and evaluation summaries.
  • To provide interviewer dashboards for ranking and review.
  • To keep the system usable even when external AI services fail.

Phase 2: Requirement Analysis (SRS)

Functional Requirements

  • The system should allow the interviewer to create, update, and manage interview sessions.
  • The system should allow question generation from a job description.
  • The system should allow manual editing of generated questions and criteria.
  • The system should allow the candidate to register through a unique interview link.
  • The system should optionally analyze resume information and create candidate-specific questions.
  • The system should conduct the interview using avatar playback, text-to-speech, and speech recognition.
  • The system should record candidate response media and transcripts.
  • The system should analyze each answer and return relevance, accuracy, confidence, keyword match, strengths, and improvements.
  • The system should generate interview summaries and candidate rankings.
  • The system should store integrity events and compute an integrity score for human review.

Non-Functional Requirements

  • Performance: Question loading, candidate registration, and result viewing should be fast enough for normal browser usage.
  • Usability: The interface should be simple for both interviewer and candidate.
  • Reliability: Sessions and candidate records should remain available through storage fallback options.
  • Security: Sensitive configuration such as API keys must remain on the backend side.
  • Scalability: Serverless API design should support growth in candidates and sessions.
  • Maintainability: The system should be modular so services, pages, and endpoints can be improved independently.

SRS Purpose

The Software Requirement Specification helps define what the system must do before coding. It acts as a clear reference for the interviewer workflow, candidate workflow, AI integration, data storage, and testing goals. By preparing requirements in advance, the project becomes easier to design and implement in a structured way.

Algorithms Used in This Project

1. AI Question Generation Algorithm

The project generates interview questions from a job description using an API endpoint. If the AI service is available, the backend sends the job description to the model and receives structured questions. If the AI service fails, a local fallback algorithm extracts role title, skill keywords, and responsibility hints from the text, then creates question templates around those detected skills.

2. Resume Personalization Algorithm

The project analyzes the resume to extract skills, projects, and resume-specific questions. In fallback mode, the local algorithm searches for known technologies such as React, Node.js, SQL, AWS, and similar keywords. It also scans lines that look like project descriptions and then builds personalized questions from those detected skills and projects.

3. Response Scoring Algorithm

The main scoring formula combines multiple factors:

Overall Score = (0.25 x Relevance) + (0.30 x Accuracy) + (0.20 x Confidence) + (0.25 x Keyword Match)

The result is then adjusted using question weight. If server-side AI scoring is available, the backend returns structured analysis. If not, the local algorithm calculates keyword match from expected keywords, confidence from positive and negative speaking indicators, relevance from overlap between question words and answer words, and accuracy from a combination of relevance and keyword match.

4. Candidate Ranking Algorithm

Candidate ranking is based on overall score. The ranking function sorts candidates in descending order and assigns rank 1 to the highest score, rank 2 to the next candidate, and so on. This allows the interviewer to review the best performing candidates first.

5. Integrity Score Algorithm

The integrity module groups captured events and applies weighted penalties. Different event types such as phone detection, gaze anomaly, audio anomaly, and tamper suspicion are multiplied by separate weights. The final score is calculated as 100 minus total weighted risk. This means more suspicious events reduce the integrity score, but the result is still used only for human review rather than automatic rejection.

6. Server Reverification Algorithm

The server receives sampled integrity frames and checks whether a frame looks like a valid phone detection event with enough confidence and a bounding box. It then returns additional server-side review events. If the server detects more phone events than the client reported, the discrepancy contributes to tamper suspicion in the final integrity score.

Phase 4: Implementation and Testing

Implementation

In the implementation phase, the design is converted into actual code. This project uses React and Vite for the frontend, JavaScript services for media and AI utilities, Node-based backend APIs for server logic, and MongoDB or JSON storage for persistence. The application supports both local development and deployable API routes.

  • The interviewer module was created for dashboard, avatar training, session creation, and candidate review.
  • The candidate module was created for registration, interview participation, and completion summary.
  • The AI module was created for question generation, resume analysis, response scoring, summary generation, and ranking.
  • The media module was created for speech synthesis, speech recognition, and recording support.
  • The integrity module was created for event capture, event upload, and integrity score computation.

Testing

Testing is done to verify that the system works according to the requirements. Both functional behavior and fallback behavior are important in this project because many features depend on browser APIs and backend AI services.

Test Case Expected Result

Trigger fallback mode by AI failure The system should still generate questions or score answers through local heuristics.
Upload integrity events The system should process events and return server-side reverification output.

1. Problem Definition & Objectives

Clarity of Problem Definition

Outcome: PO1
Current Recruitment Challenges
  • High HR Effort: Early-stage screening still consumes large amounts of interviewer time for repeated first-round conversations.
  • Inconsistent Evaluation: Different interviewers emphasize different criteria, making candidate comparison harder.
  • Low Scalability: A live panel cannot comfortably handle a large candidate pool in parallel.
  • Weak Candidate Experience: Simple forms and MCQs remove the conversational feel of a real interview.
  • Review Blind Spots: Remote interviews need better visibility into transcripts, recordings, and suspicious behavior signals.
Problem Statement & Objectives
  • Core Goal: Build a browser-based platform that lets interviewers create one interview flow and evaluate many candidates asynchronously.
  • Humanized Interaction: Reuse interviewer image or recorded video plus browser speech playback so the interview feels guided rather than form-based.
  • Smarter Question Design: Generate role-specific questions from the job description and optionally personalize extra questions from the candidate resume.
  • Automated Assessment: Score answers with structured AI analysis and fall back to local heuristics when the API is unavailable.
  • Integrity Support: Capture phone-detection and interview-behavior signals to assist review without replacing human judgment.

2. Project Concept & System Design

Description of Project Concept - Architecture & Workflows

Outcome: PO4
System Architecture Diagram

1. Interviewer Portal

Create sessions, question weights, keywords, time limits, and evaluation criteria.

Save interviewer profile, avatar image or video, and public interview link settings.

→

2. API + Storage Layer

Node and Vercel endpoints call OpenAI for question generation, resume parsing, and answer scoring.

Persist sessions and candidates in MongoDB when configured, otherwise local JSON or browser storage.

→

3. Candidate Interview Loop

Candidate opens a shared link, registers, optionally uploads a resume, grants consent, and enters the interview room.

Avatar playback, speech recognition, timers, and recording capture the answer workflow.

→

4. Review + Ranking

Each answer is analyzed, interview summaries are generated, integrity signals are aggregated, and candidates are ranked.

Local fallback scoring keeps the interview usable if AI endpoints fail.

Primary flow: job description or resume input -> question generation -> recorded candidate responses -> AI analysis, integrity review, and shortlist dashboard.
Implementation Modules
  • Interviewer Side: Dashboard, session editor, avatar training, candidate tracking, and settings.
  • Candidate Side: Registration, interview room, transcript capture, and completion summary.
  • AI Services: Question generation, resume analysis, response evaluation, and interview summary.
Workflow Highlights
  • Resume Personalization: Candidate-specific questions are appended without duplicating base session questions.
  • Integrity Pipeline: Client phone events can be rechecked by the server before computing final signals.
  • Portable Deployment: The same flow works in local development, LAN mode, or Vercel deployment.

2. Project Concept & System Design

Description of Project Concept - AI Scoring & Avatar Tech

Outcome: PO4
Avatar Playback & Speech Pipeline
  • Avatar Configuration: Interviewers can upload a cover image or record video to brand the interview experience.
  • Speech Output: Web Speech API reads each question with browser voices and replay support.
  • Visual Feedback: Speaking indicators, subtitles, and video playback create a guided interview feel.
  • Answer Capture: MediaRecorder stores video and audio while speech recognition builds the transcript used for scoring.
Multi-Dimensional Candidate Assessment
  • Server AI Output: Structured JSON scores relevance, accuracy, confidence, keyword match, strengths, and improvements.
  • Local Fallback: Keyword, confidence, relevance, and skill heuristics reproduce a usable score path during API failure.
  • Weighted Formula: Overall score uses relevance 25%, accuracy 30%, confidence 20%, and keyword match 25%, then applies question weight.
  • Interview Summary: Per-question results roll up into average metrics, top strengths, top improvements, and skill trends.
Question Input Job description, manual question bank, and optional resume profile
Answer Signals Transcript, response length, keyword coverage, and media capture
Integrity Signals Phone-detection events, anomaly markers, and server reverification
Output Ranked candidates, evidence summary, and reviewable recordings

3. Literature Survey & Related Work

Study of the Literature Survey - Identified Gaps

Outcome: PO5
Gap 1: Depersonalization
  • Existing State: Automated interview systems often reduce the process to forms or generic chatbots.
  • Our Solution: The project keeps a recognizable interviewer presence through avatar media, subtitles, and guided speech playback.
Gap 2: Single Cloud Dependency
  • Existing State: Many AI interview tools depend on a single cloud path for both generation and evaluation.
  • Our Solution: This system adds local question and scoring heuristics so interview flow remains usable when AI calls fail.
Gap 3: Remote Cheating Visibility
  • Existing State: Asynchronous tools give interviewers little context about off-screen assistance or suspicious behavior.
  • Our Solution: The app records phone-detection and anomaly events, then combines them into an integrity score for manual review.

4. Project Feasibility Analysis

Project Feasibility - Technical & Operational

Outcome: PO2
Technical Feasibility & Architecture
  • Frontend Stack: React 18, Vite, TailwindCSS, React Router, and reusable UI components support fast development.
  • Native Browser APIs: Web Speech and MediaRecorder reduce dependency on external client SDKs.
  • Backend Options: Local Node HTTP server for development plus Vercel-style API routes for deployment.
  • Persistence Layers: MongoDB for shared data, JSON file fallback on the local server, and localStorage for browser-side continuity.
  • AI Integration: OpenAI structured JSON calls power question generation, resume extraction, and response analysis.
Operational & Usability Feasibility
  • Zero Friction: Candidates join by URL without account creation or software installation.
  • Practical Workflow: Interviewers can generate questions, edit rubrics, share links, and review candidates from one portal.
  • Cross-Device Use: LAN mode and deployable API routes make demos and shared review feasible.
  • Failure Tolerance: When AI services are unavailable, local generators and scorers preserve a simplified interview workflow.

4. Project Feasibility Analysis

Project Feasibility - Economic, Legal & Ethical

Outcome: PO2
Economic Feasibility & ROI
  • Minimal Infrastructure: The platform can run locally for demos and development, reducing early hosting overhead.
  • Selective AI Usage: AI calls are limited to question generation, resume analysis, and answer scoring rather than continuous live streaming.
  • Client-Side Offloading: Speech playback, transcription, recording, and most integrity capture run in the browser.
  • Operational ROI: One interviewer can review more candidates asynchronously instead of scheduling repeated live screening calls.
Legal, Ethical & Privacy Feasibility
  • Consent-Driven Flow: Candidate registration explicitly requests consent before integrity monitoring is activated.
  • Privacy Boundaries: The system stores only the signals needed for review and supports local-first operation during development.
  • Human Review Required: Integrity limitations are documented; suspicious events support interviewer review and are not auto-rejection rules.
  • Bias Reduction Goal: Structured rubrics and transcript-based scoring improve consistency, but human oversight is still necessary.
